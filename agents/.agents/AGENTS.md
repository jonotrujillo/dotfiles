# Global preferences

## Tooling

- Tooling facts: eza, bat, fzf, zoxide and starship are in use, and `ls` and `cat` are aliased (to eza and bat). Use `command ls` or `command cat` for plain output.

## Git

- One logical change per commit. When I ask for several changes, commit them separately.
- Use `glab` for GitLab repos (MRs) and `gh` for GitHub repos (PRs).

## Verification

- Verify claims against the code before stating them. Say what is verified and what is assumed.
- For bot or review comments, say whether the issue is real before proposing a fix.

## External posts

- Show a draft first, then create or post only after I approve.
- Never send Slack messages on my behalf, even with approval. Draft the text for me to send myself.

## Code comments

- Comment only the why, never the what, and keep comments relevant long after the task is done. Reference a ticket or MR only when it explains a lasting reason, such as a workaround or known limitation. Never describe the task or review feedback that prompted the change.
